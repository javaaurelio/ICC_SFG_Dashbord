🏭
Produtor (Trading Partner)

Quem produz os dados. É o sistema ou parceiro que origina os arquivos e os entrega ao SFG para distribuição.

No SFG ele é cadastrado como um Trading Partner com flag isInitiatingProducer = true. Isso significa que ele toma a iniciativa de enviar — seja colocando arquivos em um diretório NFS, enviando via SFTP, CD ou Azure.

  • Tem um mailbox (host de entrada) criado automaticamente pelo canal
  • O FSA (FileSystem Adapter) fica de olho na pasta de origem e, quando encontra arquivo, deposita no mailbox do produtor
  • O Schedule define o intervalo de coleta (ex: a cada 5 minutos)

No código: partnerName = produtor + "_" + cdIntegracao

📦
Consumidor (Trading Partner)

Quem recebe os dados. É o sistema ou parceiro que consome os arquivos produzidos — seja gravando num diretório NFS, num bucket Azure ou disponibilizando via portal Browser.

No SFG ele é cadastrado como Trading Partner com flag isListeningConsumer = true (NFS/AZURE) ou isInitiatingConsumer = true (BROWSER — ele que "puxa").

  • NFS: o SFG extrai o arquivo para o diretório informado em customProtocolExtensions
  • BROWSER: o parceiro acessa o portal e baixa manualmente
  • AZURE: o SFG envia para um bucket via ObjectStore Adapter

No código: partnerName = consumidor + "_" + cdIntegracao

📐
Template de Integração

O modelo que define as regras do canal. É um artefato pré-criado no SFG que diz como o arquivo vai ser roteado — quais protocolos são aceitos, como o arquivo é processado, etc.

Os templates usados neste sistema:

TemplateQuando usarZIP
T_SIMPLES_INFRA_PROTOCOLO Fluxo padrão com protocolo dinâmico (NFS, BROWSER, AZURE) —
T_SIMPLES_INFRA_PROTOCOLO_ZIP Igual ao acima, mas comprime o arquivo em ZIP antes de entregar ao consumidor ✅ Ativo quando chkAtivoZIP = true

O template é informado no canal pelo campo templateName. Os provisioningFacts passam o tipo do protocolo (NFS, BROWSER, AZURE) para que o template saiba como rotear.

🔀
Canal de Roteamento

O componente que faz a ligação entre Produtor, Template e Consumidor. Sem o canal, o produtor e o consumidor existem mas não há fluxo entre eles.

Ao criar o canal via POST /routingchannels/, o SFG:

  • Cria automaticamente um mailbox para o produtor (caminho derivado do template)
  • Aplica as regras do template escolhido
  • Associa os provisioningFacts que determinam qual BP será executado para entregar ao consumidor

O mailboxPath gerado pelo canal é retornado via GET /routingchannels/ e é essencial para configurar o FSA (agendador de coleta) — é por ele que o produtor deposita os arquivos.

Resumo: Produtor deposita no mailbox → Template roteia → Consumidor recebe.

🗜️
Opção ZIP

Comprime o arquivo em ZIP antes de entregá-lo ao consumidor. Ativado pelo checkbox chkAtivoZIP no formulário.

Quando marcado, o sufixo _ZIP é adicionado ao nome do template:

T_SIMPLES_INFRA_PROTOCOLO → T_SIMPLES_INFRA_PROTOCOLO_ZIP

Isso faz com que o SFG aplique um BP de compressão antes de rotear o arquivo para o destino. O produtor não precisa saber disso — ele envia o arquivo normalmente. A compressão acontece dentro do SFG.

No código: if (chkAtivoZIP) templateNameTXT += "_ZIP"

📬
Mailbox (host do Produtor)

Área de staging dentro do SFG onde o arquivo fica temporariamente antes de ser entregue ao consumidor.

O mailbox é criado automaticamente quando o canal é criado. O caminho (producerMailboxPath) é obtido via GET /routingchannels/ logo após a criação do canal.

Esse caminho é usado em dois lugares:

  • FSA (FileSystem Adapter): campo instParms.userParm2 — o FSA deposita o arquivo aqui
  • Schedule: campo MBX_Produtor — o agendador sabe onde procurar o arquivo

Exemplo de valor: /Producao/NFS_PARCEIROS/produtor_XYZAB

Passo a passo para criar uma integração
1
📤 Informe o Nome do Produtor

No card Produtor (lado esquerdo da tela), preencha o campo "Nome Produtor" com o identificador do sistema ou parceiro que vai enviar os arquivos.

  • Use somente letras, números e underline. Sem espaços.
  • Exemplo: ARMEX, FGTS, SISTEMA_XYZ
  • Clique em Check para verificar se o nome já está em uso no SFG. Se aparecer ✅ "Disponível", está pronto para continuar.
💡 O nome final cadastrado no SFG será SISTEMA_XYZ_<código> — o código de integração é adicionado automaticamente.
2
🔌 Escolha o Protocolo do Produtor e preencha os campos

Selecione a aba do protocolo pelo qual o Produtor vai enviar os arquivos:

🟢 NFS
  • Pasta Origem: caminho completo no NFS onde o Produtor depositará os arquivos
    /NFS/PARCEIROS/SISTEMA_ORI
  • Agendar a cada: intervalo de coleta em minutos (padrão: 5)
  • Clique Check para validar o caminho
🟣 Browser
  • Sem campos extras — o Produtor envia acessando o portal web
  • As credenciais de acesso (login/senha) são exibidas automaticamente após preencher o nome do Produtor
🟠 Azure
  • EndPoint URL: URL do storage Azure
  • Bucket Name: nome do container/bucket
  • SecretKey: chave de acesso
  • CA Certificate: arquivo .cer/.crt do certificado
  • Pasta Origem: diretório de coleta no bucket
  • Pasta Arquivado: diretório para mover após coleta
  • Agendar a cada: intervalo em minutos
⚠️ SFTP e CD estão disponíveis na interface mas ainda não implementados nesta versão.
3
📥 Informe o Nome do Consumidor

No card Consumidor (lado direito da tela), preencha o campo "Nome Consumidor" com o identificador do sistema ou parceiro que vai receber os arquivos.

  • Mesmas regras de nome do Produtor: sem espaços, sem caracteres especiais.
  • Clique em Check para verificar disponibilidade.
💡 O checkbox ZIP fica logo abaixo do nome do consumidor. Marque-o se quiser que o arquivo seja comprimido em ZIP antes de chegar ao consumidor.
4
🔌 Escolha o Protocolo do Consumidor e preencha os campos

Selecione a aba do protocolo pelo qual o Consumidor vai receber os arquivos:

🟢 NFS
  • Pasta Destino: caminho completo no NFS onde o SFG vai entregar os arquivos
    /NFS/PARCEIROS/SISTEMA_DEST
  • Clique Check para validar o caminho
🟣 Browser
  • Sem campos extras — o Consumidor baixa os arquivos acessando o portal web
  • As credenciais de acesso são exibidas automaticamente após preencher o nome do Consumidor
🟠 Azure
  • EndPoint URL: URL do storage Azure de destino
  • Bucket Name: nome do container de destino
  • Pasta Destino: subdiretório dentro do bucket
  • SecretKey: chave de acesso
  • CA Certificate: arquivo .cer/.crt
5
🗜️ ZIP (opcional) — marque se quiser compressão

O checkbox ZIP está no card do Consumidor, logo abaixo do nome. Se marcado, o SFG comprime o arquivo antes de entregá-lo ao destino.

  • O Produtor não precisa fazer nada diferente — a compressão acontece dentro do SFG
  • Internamente o template muda de T_SIMPLES_INFRA_PROTOCOLO para T_SIMPLES_INFRA_PROTOCOLO_ZIP
✓
✅ Clique em "Criar Integração"

Com todos os campos preenchidos, clique no botão verde "✅ Criar Integração" no centro da tela, entre os dois cards.

  • Um spinner de carregamento aparece enquanto as APIs são chamadas em sequência
  • Se tudo der certo, um pop-up verde de Sucesso é exibido
  • Se houver erro (campo inválido, serviço indisponível etc.), um pop-up vermelho mostra o detalhe do problema
💡 Após criar, o código da integração fica visível no topo da página (ex: XYZAB). Guarde esse código — ele identifica a integração no SFG.
